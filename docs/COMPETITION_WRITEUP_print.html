# MedAssist - Offline AI Clinical Triage Assistant
## Competition Write-up (3-page format)

### Project Summary
MedAssist is an offline-ready, human-centered AI clinical triage and decision support application for low-resource healthcare environments. The system combines a production-structured full-stack application (React + FastAPI) with MedGemma (HAI-DEF) integration and a safety-first output pipeline designed for real-world deployment constraints.

This tool is explicitly **not a diagnostic system**. It supports frontline clinical reasoning by structuring patient context, surfacing urgency, identifying red flags, and suggesting next steps while preserving clinician authority.

---

## 1. Problem Definition and User Need
Many rural and low-resource clinics operate under one or more of the following constraints:
1. Limited specialist access.
2. Intermittent or low-bandwidth internet.
3. Privacy and infrastructure barriers to cloud-only models.
4. High cognitive load during triage with variable decision consistency.

The target user for MedAssist is a frontline clinician or healthcare worker performing first-contact triage. The unmet need is not a replacement for physicians; it is a reliable clinical decision-support layer that improves consistency, prioritization, and communication quality.

### Why AI is appropriate
Triage requires rapid synthesis of multimodal patient context (symptoms, duration, vitals, history). This is a high-friction workflow where AI can add value by:
1. Structuring reasoning quickly.
2. Highlighting likely risk signals.
3. Standardizing output format for handoff and escalation.
4. Producing patient-friendly language for communication.

---

## 2. Effective Use of HAI-DEF Models
MedAssist uses **MedGemma** from Google Health AI Developer Foundations (HAI-DEF) as its clinical reasoning engine. This directly satisfies the mandatory model-use requirement.

### Why MedGemma
1. Healthcare-oriented open model family.
2. Flexible local/developer-controlled deployment pathways.
3. Suitable for practical triage narrative generation and clinical summarization.

### How MedGemma is used in this project
1. Triage summary generation.
2. Differential diagnosis hypothesis generation (top 3).
3. Next-step recommendation generation.
4. Optional patient-friendly explanation mode.

### Engineering note
In deployment-constrained contexts, model output formatting may degrade. MedAssist includes an explicit schema-hardening and safe-fallback layer, so safety-critical UI sections remain structured and operational even when raw generation quality drops.

---

## 3. Solution Architecture and Product Design
### System architecture
`User -> React Frontend -> FastAPI Backend -> MedGemma Runtime -> Structured Response -> UI Rendering`

### Stack
1. Frontend: React (Vite), TailwindCSS.
2. Backend: FastAPI, Pydantic schemas, structured logging, `.env` configuration.
3. AI runtime paths:
   1. Transformers path for MedGemma.
   2. Optional GGUF path for constrained local environments.
   3. Fallback mode for guaranteed local operability.
4. Deployment: Dockerized local setup with reproducible instructions.

### Product-level capabilities
1. Structured patient intake form with clinically relevant fields.
2. Urgency badge visualization (`LOW`, `MODERATE`, `HIGH`, `EMERGENCY`).
3. Red-flag display and escalation guidance.
4. Optional patient-friendly explanation mode (non-technical language).
5. Enterprise workflow UI elements:
   1. Command rail.
   2. Case history queue.
   3. Critical alerts panel.
   4. Audit trail.
   5. Printable report export.

---

## 4. Safety and Guardrails
MedAssist implements safety-first behavior by design:
1. Mandatory disclaimer in both UI and output payload.
2. No medication dosage recommendation behavior.
3. No definitive diagnosis claims.
4. Required limitations section in every response.
5. Structured output validation and fail-safe fallback when model output is non-compliant.

This approach treats reliability and safe degradation as first-class requirements for low-resource healthcare environments.

---

## 5. Prompt Engineering Strategy
The backend prompt strategy uses:
1. A strict system prompt with explicit safety constraints.
2. A structured patient context block with demographics, complaints, symptoms, vitals, and history.
3. A strict JSON schema requirement to support deterministic downstream rendering.
4. Optional patient-friendly explanation mode in the request schema.

### Why this matters
Prompting is optimized for production behavior, not only benchmark-style responses. The structure ensures output sections map directly to clinical workflow components in the UI.

## 7. Hardware Requirements and Deployment Feasibility
### Recommended
1. GPU with sufficient VRAM for quantized runtime.
2. 16GB+ RAM.
3. 20GB+ storage.

### Real-world deployment feasibility
MedAssist is designed with a dual-path strategy:
1. Local/offline-capable app path for constrained environments.
2. GPU-backed MedGemma proof path via Colab for reproducibility and model-use validation.

This improves feasibility for teams that cannot maintain constant high-end inference infrastructure at the point of care.

---

## 8. Limitations
1. The system is decision support, not diagnosis.
2. Raw model generation can still show output-format reliability challenges under strict JSON constraints.
3. Performance quality varies by runtime/hardware and generation stability.
4. Evaluation data is simulated and does not replace prospective clinical validation.
